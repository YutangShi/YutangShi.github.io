Prompt 工程不是玄學，核心是把需求寫成「可被執行」的規格。

## 你看完會得到什麼

- 你會知道什麼叫「高穩定 Prompt」，不是碰運氣。  
- 你會學到一個固定模板：任何工作都能套用。  
- 你會拿到 3 個辦公場景可直接複製的 Prompt。  
- 你會避開 3 個最常見的誤解，少走彎路。

## 先懂的名詞（每個 2 句內）

1. Prompt：你寫給 AI 的需求單，不只是問一句話。寫越清楚，答案越可用。  
2. 結構化：把「角色、目標、格式、限制」固定成欄位。這能讓輸出更穩定、也更容易重複使用。  
3. 範例（Example）：在 Prompt 裡附上一小段示範輸入或示範輸出。它會讓 AI 更容易「照著做」。  
4. 驗收標準：你用來判斷答案合不合格的條件。沒有驗收，就只能憑感覺。  
5. Few-shot：給 AI 1 到 3 組小範例，讓它模仿格式與風格。白話來說就是「先給它看你要的樣子」。

## 結構化 Prompt（先定義）

![Prompt 結構示意圖](/images/blog/diagrams/prompt-anatomy.svg)

```text
角色：你是資深內容編輯。
任務：把會議逐字稿整理成可執行的會議紀要。
輸入：{meeting_transcript}
輸出：
- 三行摘要
- 決策事項（條列）
- 待辦清單（負責人/截止日）
- 風險與阻塞點
規則：
- 不可捏造人名與日期
- 不確定資訊標記為「待確認」
- 請使用繁體中文
```

## 高穩定 Prompt 的 4 個元素（你可以當成檢查表）

1. 角色：讓模型知道要扮演誰。  
2. 任務：一句話講清楚目標。  
3. 輸出格式：讓結果可直接貼到文件或系統。  
4. 邊界條件：明確禁止捏造、要求標記不確定資訊。

## 真實場景例子（3 個）

### 例子 1：把長 Email 變成可回覆草稿

```text
角色：你是我的 Email 助理。
目標：把以下信件整理成我可以直接寄出的回覆草稿。

背景/輸入資料：
{貼上對方信件}

輸出格式（務必遵守）：
1) 一句話總結對方想要什麼
2) 我的回覆草稿（3 段式：先同理、再說結論、最後下一步）
3) 我需要補問的資訊（如果有）

限制：
- 不確定資訊標記「待確認」
- 不可捏造日期、價格、承諾
- 繁體中文
```

### 例子 2：把任務拆成可執行步驟

```text
角色：你是專案教練。
目標：把「{任務}」拆成 7 個小步驟，每步驟 30 分鐘內可完成。

輸出格式：
1) 第 1 步：目標 + 產出物
2) 第 2 步：目標 + 產出物
...

限制：
- 需要外部資料的地方，請標記「需提供資料」
```

### 例子 3：把會議逐字稿變成「決策 + 待辦」

```text
角色：你是 PM 助理。
目標：把會議逐字稿整理成可執行紀要，讓沒有參加的人也看得懂。

背景/輸入資料：
{貼上逐字稿}

輸出格式：
1) 三行摘要（講重點，不講過程）
2) 決策事項（條列）
3) 待辦清單（負責人/截止日；不知道就寫待確認）
4) 風險與阻塞（含需要誰協助）

限制：
- 不可捏造人名、日期
- 不確定資訊標記「待確認」
```

## 你可以直接套用的 Prompt 骨架（萬用模板）

```text
你是{角色}。
請完成{任務}。
輸入資料：{資料}
輸出格式：{格式}
限制條件：{限制}
品質標準：{驗收方式}
```

## 常見誤解（至少 3 點）

1. 「我中文講清楚就好，不用格式。」  
沒有格式時，AI 會用它的習慣回你一大段，你很難直接用在文件或系統。  

2. 「AI 回得很有自信，所以應該是對的。」  
自信不等於正確。你要用限制條件與資料來源，降低它亂補的機率。  

3. 「一次把所有事情都問完，省時間。」  
任務越大，越容易混在一起。拆成小步驟反而更快得到可用成果。  

## 下一步學習建議（3 條）

1. 選 1 個你每天都會做的任務（Email、會議、週報），固定用同一個模板跑 7 天。  
2. 每次把「失敗案例」記下來：是哪個欄位沒寫清楚（角色/輸出/限制/資料）。  
3. 只要能穩定產出，就把模板放到你的 SOP 或自動化工具（例如表單、Notion、n8n）裡。
