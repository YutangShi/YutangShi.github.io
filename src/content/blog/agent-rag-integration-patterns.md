代理系統最容易失敗的原因，不是模型不夠強，而是流程邊界不清楚。

## 你看完會得到什麼

- 你會知道 Agent 是什麼，以及它和聊天機器人差在哪。  
- 你會理解 RAG 在哪裡派上用場，以及它不是「萬能補丁」。  
- 你會拿到一個「可執行代理」的設計模板：模型職責、工具、護欄、升級條件。  

## 先懂的名詞（每個 2 句內）

1. Agent：會把任務拆成步驟，並在過程中呼叫工具執行。白話是「不只回答，還會做事」。  
2. Tool：Agent 用來查資料或做動作的能力，例如查訂單、送通知、寫工單。每個 Tool 都要定義輸入與輸出。  
3. RAG：先從文件或知識庫找資料，再生成回答。重點是可追溯，避免憑空亂說。  
4. 護欄：限制 Agent 不能做什麼，或什麼情況要停下來問人。護欄越清楚，翻車越少。  
5. 升級條件：碰到高風險、資料不足或需要授權時，交給人處理。這是把風險控住的關鍵。

## 結構化 Prompt（先定義）

```text
角色：你是 AI 代理架構師。
任務：把「客戶問題處理」設計成可執行代理流程。
輸出：
- 模型職責
- 工具清單（每個工具的輸入/輸出）
- 指令與護欄
- 何時升級人類接手
限制：高風險操作必須有人工確認步驟。
```

## 代理最小可行架構

- Model：負責判斷與決策。  
- Tools：負責查資料、呼叫 API、發送通知。  
- Instructions：負責邊界、語氣、規則與風險控制。

## RAG 的位置

RAG 不是萬能補丁，而是讓回答更可追溯的資訊管道。  
先定義資料來源品質，再做檢索與生成。

## 真實場景例子（3 個）

1. 客服：收到客訴后，Agent 先分類，再查訂單與政策，最後產回覆草稿並標記來源。  
2. IT 工單：使用者報修，Agent 先問 3 個必問問題，再查知識庫，必要時升級給值班工程師。  
3. 內部搜尋：同事問「公司規範怎麼寫」，RAG 提供引用段落與連結，避免口耳相傳。  

## 常見誤解（至少 3 點）

1. 「模型很強，所以不需要護欄。」  
模型越強，做錯事也可能做得更快。高風險操作一定要有人工確認。  

2. 「RAG 可以解決所有正確性問題。」  
如果資料來源不可靠，檢索再準也沒用。先整理資料品質，再談 RAG。  

3. 「先把所有工具都接上，功能越多越好。」  
工具越多，失敗點越多。先從 1 到 3 個高價值工具開始，逐步擴充。  

## 下一步學習建議（3 條）

1. 先做一個最小 Agent：只拆解任務、不做高風險動作，所有操作都先給人確認。  
2. 定義每個 Tool 的介面：輸入、輸出、錯誤處理、重試策略。  
3. 導入 RAG 時先做「引用與追溯」：每個關鍵結論都能回到原始文件。
